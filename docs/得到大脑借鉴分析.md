# 「得到大脑」借鉴分析（对应 V0.9.0）

> 对照产品：得到大脑（biji.com）
> 对照对象：随手记 V0.9.0（versionCode 20）
> 目的：说清楚哪里像、哪里必须不一样、这一版照它改了什么

---

## 一、相同之处

两个产品解决的是同一个问题：**人有一些想法，但想法停在碎片状态，长不成能说出口的东西。**

| 维度 | 得到大脑 | 随手记 | 判断 |
|---|---|---|---|
| 入口 | 随手记一条，不要求成篇 | 随手记一条，不要求成篇 | 一致，且都是刻意的 |
| 单位 | 一条笔记 = 一个思考种子 | 一条记录 = 一个思考种子 | 一致 |
| AI 角色 | 不代写，做扩展与追问 | 不代写，做追问与重组 | 一致 |
| 素材来源 | 用户自己的历史笔记 | 用户自己的历史记录 | 一致 |
| 输出 | 卡片 / 长文 | 文章 / 拍摄选题 | 分叉点，见下 |

**最核心的一致**：都不把「写下来」当终点。写下来只是把原料放进机器，机器要转出东西来。

---

## 二、必须不一样的地方

「得到大脑」的后半段是**知识管理**——笔记之间建立连接，形成知识网络，服务的是"我懂了什么"。

随手记的后半段是**表达**——追问想清楚，成文说清楚，转选题拍出来，服务的是"我说清楚了什么"。

这个差别决定了很多设计不能照搬：

| 得到大脑的做法 | 为什么不能直接搬 |
|---|---|
| 笔记之间双向链接、知识图谱 | 我们的用户不是在建知识库，是在准备拍视频。图谱对他的下一步没有帮助，反而制造"要整理"的压力 |
| 卡片可以无限生长、长期演化 | 我们的记录有明确的窄出口：一条记录 → 一个选题 → 一条视频。无限生长会让人停在原地 |
| 重「知识沉淀」的统计 | 我们的统计只给客观数据（拍了几条、连续几天），**不做质量评分**——评分会让人不敢发 |

一句话：**它做加法，让人知道得更多；我们做减法，让人敢说出口。**

## 三、这一版照它改了什么

### 1. 发芽（直接借鉴，已落地）

它的「发芽」是：从你的一句话出发，跨领域、跨时空地长出连接，**每条连接必须带出处**。

我们按同一模型实现，但把用途拧向表达：

- 三段式：`种子`（你原话里的哪一句）→ `洞察`（它连到了什么）→ `出处`（谁说过、哪本书、什么现象）
- 硬规矩写进 prompt：**没把握就把出处留空，绝对不许编造书名、人名、数据、年份**
- 一条记录可以发很多次芽，每次追加、不覆盖——**每次发芽都是那一刻的认知状态**
- 报告读完可以「接着这句记一条」，把芽变成新种子

**刻意做的一个减法**：发芽**不参与**记录的完成度计算。它是一条旁路，不是流程的一环。否则用户会觉得"不发芽这条记录就没做完"。

### 2. 「AI 追问太浅」的根因修法（借鉴它的提问策略）

原来的问题不是模型不行，是我们没把材料喂全：

- 追问请求只发了「本轮对话」，**原始记录在第二轮之后就消失**——模型只能贴着上一句话猜
- 同一个意思被换词重问，用户答两遍会觉得被糊弄

改法：

- `originalNote` 固定为第一条 user 消息，每一轮都带
- 把**已经问过的问题列表**传给模型，明确禁止换词重问
- prompt 里加了一条动作指令："动手之前，先在脑子里过三遍整段记录，找出最经不起推敲的那一处"
- 加了三段自检：这句是不是他上一句的复读？换个人说是不是也成立？他答短了是不是因为我问得太宏大？

### 3. 去线性化（借鉴它的「多入口」而非「下一步」）

它的一条笔记下面挂的不是一个「下一步」按钮，而是多个平级的 AI 动作。

我们照着改了三个地方：

| 位置 | 改之前 | 改之后 |
|---|---|---|
| 记录详情页 | 底部一个主按钮「AI 追问」 | 三个并列：编辑 / 发芽 / 继续聊 |
| 成文页（已有文章） | 底部「存进思考库」——但文章已经在库里了 | 主按钮「转成一条选题」+ 次行「回去再聊」「导出 .md」 |
| 保存文章 | 存完自动跳走 | 存完留在原地，让你决定下一步 |

**「存进思考库」这一条是明确的 bug**：从「思考」tab 点进一篇文章，最下面还是「存进思考库」，而它本来就在库里的。现在按 `alreadyComposed` 分流：没存过才显示保存条，存过就显示动作组。

## 四、想要但这一版没做的

按优先级排：

1. **拍摄后的回放对比**（P2，最大的留存风险）
   App 不负责拍摄，用户用手机相机拍完回来点「我拍好了」。但点完之后没有任何反馈——这是已知的最严重产品缺口。比任何 AI 功能都重要。

2. **记录之间的连接**
   它最值钱的部分。但我们现在的出口太窄（一条记录一个选题），先补连接会让人停在"整理"里。等用户真的有几十条记录、开始问"我以前是不是说过类似的"时再做。

3. **跨记录的长期主题**
   一年后回看"你反复在说的事"。数据量不够时做出来是空的。

---

## 五、一句话总结

借鉴的是它的**手法**（发芽、多入口、追问到底），不是它的**目的**（建知识库）。
我们的目的始终只有一个：让一个说不清楚的人，能对着镜头说清楚三分钟。
