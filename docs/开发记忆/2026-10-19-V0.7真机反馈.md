# 2026-10-19 V0.7：真机实测反馈修复

**271 条测试全绿**。提交 `6b04464`。APK：`outputs/suiji-v0.7.apk`

真机实测是第一次在真实环境验证，暴露了模拟器测不出的问题。

## 阻塞性 bug

### 记录条消失（bug 6）

根因：`record` tab 用 deepeningQueue，只显示 WAIT 状态。
一旦深化或成文就消失——用户以为记录丢了。

**记录 tab 是「我记过的东西」的清单，不是流水线的一环。**
状态一直在变，但「我记过它」这件事不该变。

改成 recordTimeline（全部状态 + 时间倒序），加 2 条回归测试。

### 无法进入 AI 追问（bug 7）

根因：`load()` 只加载数据，**不发起第一次追问**。
用户看到空白页 + 一个输入框，不知道该输入还是该等，于是卡住。

改成进入页面自动发起第一个问题。
输入框在 answeredCount == 0 时禁用——
那时用户还没看到问题，输入了也不知道回什么。

placeholder：「AI 正在想第一个问题…」→ 有问题后→「回应它」

### 返回手势不能一律退回首页

```
Detail→Home  Edit→Detail  Deepening→Detail  Compose→Deepening  Convert→Compose
```

一律退首页会让人从成文页一路滑到首页，而不是回到追问页。

### 数字角标为什么去掉

**角标是别人的 KPI，不是用户的需要。**
用户看到数字会当成「欠了任务」，产生压力而不是行动；
记录 tab 显示全部想法（不是待办队列），数字在那里没有语义。

## DeepSeek 选 flash 不选 pro

追问是**流式逐字浮现**的。Pro 的推理深度对追问+润色没实质帮助，
但首字延迟明显更长——而那个延迟落在最关键的位置：
**用户发出话之后的第一次等待**。等太久就以为卡死了，然后就退出了。

候选：deepseek-flash（推荐）/ deepseek-reasoner

## 追加：Room 迁移 bug（模拟器测不出，真机才炸）

改了 provider 表主键（单列→复合键）以支持多模型，
**但忘了升 Room 的 version**。

覆盖安装到有旧数据的设备上，App 启动即崩：

    Room cannot verify the data integrity.
    Looks like you've changed schema but forgot to update the version number.

### 为什么模拟器没暴露

之前每次测试都 `uninstall` 后重装 —— 新装没旧库，不走迁移校验。

**全新安装根本不会触发迁移。** 必须用 `install -r` 覆盖升级才测得到。

### 修复

- version 1 → 2
- MIGRATION_1_2 重建 provider 表
- DI 里 addMigrations

provider 表可以重建是因为**API Key 不在里面**（在 Tink 加密 prefs），
丢的只是「选了哪个服务商」这种可重建状态。
note / deepening / article 一个都不能动。

### Modules.kt 里原本就有的注释

    // 不用 fallbackToDestructiveMigration——
    // 加字段时必须写 Migration。

那个 also{} 空块本来就是为迁移预留的位置，坑埋在那里等着。

### 教训

**schema 变更 = 升 version + 写 Migration + 用 install -r 测**

## 模拟器无网络问题

软件渲染模式下模拟器完全没有网络（连 8.8.8.8 都 ping 不通），
但宿主机正常。导致 AI 调用测不了。

这类环境问题要分清：宿主机 curl 通= 我的网络没问题，
模拟器 ping 不通 = 模拟器网络初始化失败。

## 真机测试的两个关键点

1. **覆盖安装而非重装** —— 迁移路径只有升级才走
2. **看 logcat 的 FATAL** —— 界面看着正常但进程已死（no app thread）
