## V0.12.1：成文回来一串空白（用户真机报障）

### 现象

追问 5 轮 → 点成文 → 「没写成 / 响应里没有 content 字段」＋一段原始 JSON。

### 根因（在模拟器上复现后抓到原始响应才看清）

```
"content":"      \n\n   ……"        ← 237 个 token，全是空格和换行
"finish_reason":"stop"
```

HTTP 200、正常结束、真输出了 token，只是没有一个字。

`extractContent` 用 `isNullOrBlank()`，这类响应被归成「没有 content 字段」，
和「只回了思考」「被截断」「被审核」共用一句机器话。

### 修法

1. `ResponseParser.whyNoContent()` 分四种：THINKING_ONLY / TRUNCATED /
   FILTERED / EMPTY（外加 UNDETERMINED：响应里连 choices 都没有）
2. **重试不能原样重发**——同一条请求大概率还是同一串空白。
   改为在末尾补一句纠偏话术（「上一次你什么都没写……」），既换采样也把要求说死
3. `ErrorKindLite` 补 THINKING_ONLY / NO_CONTENT，接上已有的 ErrorKind 文案

已用同一条路径在模拟器上验证：成文正常出来。

### 过程教训（比结论更值钱）

- **同一个 case 我自己用 curl 重放，8 次里 8 次正常**，但设备上稳定空白两次。
  说明「本机重放能过」不等于「服务端不会给坏响应」。
  要么复现到设备上，要么承认没结论。
- 要抓设备上的请求体，最省事的做法是临时在 `BuildConfig.DEBUG` 里打一行
  log，用完立刻删。logcat 单行会截断，超过 ~1800 字符要分块打。
- **adb pull 的落盘路径**：设了 `MSYS_NO_PATHCONV=1` 之后，`/d/work2/...`
  这种路径 adb 认不了，要写成 `D:/work2/...`。
- **`adb shell cat` 会破坏二进制**（CRLF 转换）：拉数据库必须用
  `adb exec-out run-as <pkg> cat`，否则 sqlite 打开就是 malformed。
- uiautomator dump 失败时，本地会留着上一次的旧 xml，
  看起来像「界面没变」。每次 pull 前先删本地文件。

### 端到端验证怎么造数据

中文没法用 `adb shell input text` 打进去。做法是：
force-stop → 改本地 db 副本（note + deepening 两张表，roundsJson 是
`[{"q":"...","a":"..."}]`）→ `pragma wal_checkpoint(TRUNCATE)` →
push 到 /data/local/tmp → `run-as cp` 覆盖 → 删掉 -wal/-shm → 重启应用。

只隔一个 Spacing.m，标题写长一点就和正文糊在一起。

### 建 Release 不用再问用户要 PAT

GCM 已经缓存了凭据，可以直接取出来用：

```bash
TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' \
        | GIT_TERMINAL_PROMPT=0 git credential fill | sed -n 's/^password=//p')
```

`printf` 结尾必须是**空行**（`\n\n`），否则 credential fill 会挂在等输入上。
拿到的是 classic PAT（长度 40），`Contents: Read & write` 足够建 Release + 传附件。

网络要分两路：

| 目标 | 走法 |
|---|---|
| `api.github.com` | **直连**（先 unset 全部 proxy 变量） |
| `github.com/.../releases/download/...` | **必须 socks5 代理**，它会 302 到 objects.githubusercontent.com |

用 urllib 传附件（`uploads.github.com`，`Content-Type: application/vnd.android.package-archive`），
比 curl 省心——APK 路径带中文，curl 的 `@路径` 在 Git Bash 下容易出岔子。

## V0.12.2：七条体验反馈，五条是「界面在骗人」

用户一次提了七条。逐条查下来，五条不是缺功能，而是**有个东西长得像能用、实际不生效**。

### ⚠️ prompt 里「方法段」的位置决定它有没有用

`probeSystem` 原结构：角色 → **方法段** → 一百来行共用要求 → 禁区 → 输出 → 轮次。

用户说「从苏格拉底式切到逐层逼问，追问的问题没变化」。原因不是方法段写得不够狠：

1. 共用段里有「找出**最经不起推敲**的那一处」——这本来就是 GRILL 的手法
2. 共用段给了示范问句「背下来的那些字，**是卡在嘴边，还是压根没想起来**」——
   那是二分追问，苏格拉底的招牌动作
3. 方法段排在最前面，被后面一百行冲掉

**修法：方法段移到末尾（紧挨禁区）。** 共用段只留「够不够贴」的判据，示范全删。

推论（接 V0.11 那条）：**不要只在末尾写"以某段为准"，要把强势那段真的挪到最后。**

### ⚠️ 同一个 Composable 的两个路由，参数容易漏传

成文页有两个入口：
- `Route.Compose`（刚成文）→ 传了 `onToggleChip` / `onSelectStyle`
- `Route.Article`（从思考库打开）→ **漏了**

Kotlin 给了默认值 `= {}`，所以编译不报错、界面不崩溃、芯片点下去还有涟漪，
只是什么都不发生。**默认值能救命，也能藏 bug。**

另外 `loadArticle` 压根没读 `roundCount` / `sproutCount`，芯片只能显示「追问 0 轮」。

三层叠在一起：界面上有一排"装饰"。

### ⚠️ 重写之后必须有保存入口

`compose()` 成功时没改 `alreadyComposed`。从思考库打开的文章重写后，
底部摆的仍是「转选题 / 回去再聊」，**没有保存按钮**——新正文只在内存里，
退出就没了，库里还是旧的。修完芯片才暴露出来（原来根本点不动，走不到这步）。

### 发芽：prompt 里没说拿它干什么

`draftSystem` 全文没提芽。芽只出现在 `sproutBlock` 那份清单里
+ 一句「用了要标 fromSprout」。模型当然能不用就不用。

加了 `withSprouts` 参数和一段正文：芽是**文章的骨头**，不是待引用的资料；
推进要顺着芽的连接走；「往上翻的那一层只能来自芽，不许从常识里编」。
没芽时不生成这段（讲了却没有材料，模型会自己编）。

### 拍摄骨架一大片空白：Row 里塞 N 个 Text

`Row { cues.forEach { Text(...) } }`——Text 不带权重、Row 不换行，
N 条提示各分到几十 dp，每句折成七八行，整块被撑到半屏高，
还只有前两条可见。改成一条一行。

**顺带一个坑**：`Cue.icon` 里装的不是 emoji，是「停顿」「看镜头」「手势」——
我按 18dp 分成两列后，图标列被压成两行。最后合成一行 `"${icon} ${text}"`。

### 转选题：`existing == null` 让「一篇文章多条选题」只成立一次

`load()` 里有选题就不拆角度 → 第二次进来直接落旧骨架。
现在有选题先进 `TopicStep.PICK`：「选题 1 / 选题 2 / 再拆一个新角度」。

顺手修了保存后的返回键：原来会退回角度列表（chosenAngle 没清），
让人以为刚才没存上。现在 `saveScript` 清 `chosenAngle`，返回键据此判断。

### 验证方式：uiautomator 的 bounds 能当尺子

软件渲染下截图全黑（老问题）。但 `uiautomator dump` 的树是准的，
**用元素的 y 区间就能量出「这块空白多高」**：
修前 cues 撑到 ~1300px，修后每条 90-135px。

**必须先 `rm -f /sdcard/ui.xml` 再 dump**：dump 失败（窗口没焦点时）
不写文件也不报错，`cat` 会读到上一次的树 → 表现为「界面明明变了，dump 还是老样子」。
今天就在这上面绕了几轮，最后靠 `dumpsys window | grep mCurrentFocus` 发现是 `null`。
