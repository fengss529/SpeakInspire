## 踩到的三个新坑

### 1. `extractContent` 用解引号后的值判断类型（本轮最隐蔽）

合并 JSON 扫描器时把 `ResponseParser.extractContent` 写成：

```kotlin
val v = extractField(body, key)
if (!v.isNullOrBlank() && !v.startsWith("{")) return v
```

成文/拆角度/骨架的 content **本身就是 JSON 字符串**，解完引号以 `{` 开头 → 全被丢掉。
表现：模型正常返回，解析出 0 个段落、0 个角度。8 条测试同时红。

**判断"这个值能不能当正文"必须看原始值第一个字符是不是 `"`。**
解引号之后类型信息就没了——这是把「解析」和「校验」顺序做反的典型。

### 2. 未用 import 会在改配置时集中爆出来

`compileDebugKotlin` 成功不代表测试源码能编。
`RealAiServiceTest` 里 `import com.hatio.speakinspire.service.extractField`
搬包后没跟着改，`testDebugUnitTest` 才报错。

### 3. 后台启动的模拟器会被回收

`emulator ... &` 在 Bash 工具里会被当成孤儿进程杀掉（`adb devices` 为空）。
必须用 `run_in_background: true` 走受管任务。
另外 `启动模拟器.bat` 从 Git Bash 调会被按 GBK 解码，中文行全变乱码 → 直接调
`emulator.exe -avd Pixel_7 -gpu swiftshader_indirect -scale 0.4`。
