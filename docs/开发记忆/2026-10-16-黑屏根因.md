# 2026-10-16 黑屏根因：代理环境变量

## 结论

**黑屏的真正原因不是 GPU，是 `HTTP_PROXY` / `http_proxy` 两个变量冲突。**

本机设了两套代理变量（大小写各一），模拟器启动时会因冲突而**静默退出**。

## 我走的两次弯路

### 第一次：以为参数没加对

查进程参数发现：

```
emulator.exe | gpu = NOT SET (defaults to Google Intel)
```

那个实例压根没用软件渲染启动 —— 但这只是「为什么它黑屏」，
不是「为什么加了参数还是起不来」。

### 第二次：误判成「Android 16 不支持软件渲染」

进程起来了（内存 412MB），几十秒后消失，日志停在参数打印那行。
我据此判定软件渲染在 Android 16 上不可用 —— **这个结论是错的**。

## 最有欺骗性的地方

| 观察 | 看起来像 | 实际是 |
|---|---|---|
| 进程起来了内存 400MB+ | 正常启动 | 只是 qemu 起来了 |
| 几十秒后进程消失 | 崩溃 | 静默退出，无崩溃日志 |
| 日志停在参数打印行 | 一切正常 | 之后就死了 |

**判断进程是否「启动完成」不能只看它在不在，要看 adb 是否上线。**

## 修复

启动前清掉 4 个代理变量：

```bat
set HTTP_PROXY=
set http_proxy=
set HTTPS_PROXY=
set https_proxy=
```

验证结果：

```
GLES: Google (Google Inc.), Android Emulator OpenGL ES Translator
      (Google SwiftShader), OpenGL ES 3.0 (SwiftShader 4.0.0.1)
```

截图正常。

## 本机启动模拟器的三个坑

### 1. 代理变量冲突

见上。这是静默失败，最难查。

### 2. AVD 锁文件

上次异常退出会留下 `*.lock`，导致下次启动直接失败（进程都不出现）。
脚本里要清理。

### 3. 启动方式受限

- `nohup` / `&`：进程随 shell 退出被回收 → 不能用来判断是否启动成功
- PowerShell `Start-Process`：环境变量有重复 key（大小写各一），
  它内部构造字典时抛 `已添加项。字典中的关键字` 异常
- `cmd /c start`：被安全策略禁止
- **Bash + run_in_background：可用**

## 代价

软件渲染下系统较慢，偶尔弹 `System UI isn't responding`，点 Wait 等恢复。
这是正常的，不是bug。

## 判断黑屏归属的流程

1. `adb exec-out uiautomator dump /dev/tty` 看界面树
   - **有完整文字** → App 在跑，问题在截图通道
   - **空** → 真的没渲染
2. 查渲染器：`adb shell dumpsys SurfaceFlinger | grep GLES:`
   - `Google (Intel)` → 硬件加速，有黑屏风险
   - `Google SwiftShader` → 软件渲染，截图正常
3. 查进程是否真的活着（不要只看刚启动那一刻）
