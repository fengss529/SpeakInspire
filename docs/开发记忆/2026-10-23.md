## 三个必须记住的配置

### 1. GitHub 必须绕过系统代理

本机有 `HTTP_PROXY=http://127.0.0.1:52889`（WorkBuddy 的出口代理），
它**放行国内站点、不放行 GitHub**：

| 访问方式 | 结果 |
|---|---|
| 走代理访问 baidu | 200 |
| 走代理访问 github.com | 超时（HTTP 000） |
| `--noproxy '*'` 直连 github.com | **200，但握手要 16 秒** |

所以配了：

```bash
git config --global http.https://github.com.proxy ""
```

**判断方法**：`curl -s -o /dev/null -w "%{http_code}" https://github.com`
返回 000 且超时 = 代理在拦；加 `--noproxy '*'` 能通就是代理问题，不是网络断。

### 2. 凭据用 GCM，不需要 SSH key 也不需要 PAT

`credential.helper=manager`（GCM 2.9.0 已预装）。
push 时自动弹浏览器授权，之后记住。42 秒推完，比配 SSH 快得多。

### 3. 提交身份原来是个占位值

之前是 `ahui <ahui@local>` —— 推到 GitHub 上不会关联账号。
已改 `fengss529 <fengss529@users.noreply.github.com>`。
**git 身份不跟仓库走，每台新机器都要重配一次。**

## ⚠️ gradle.properties 的本机路径已外移

`org.gradle.java.home=D:\soft\jdk21` 原来写在**项目**的 gradle.properties 里，
而这个文件是被 git 跟踪的 —— 家里 clone 下来路径就错，
报错还只有一行 `25.0.3`，根本看不出是路径问题。

已移到用户级 `C:\Users\<你>\.gradle\gradle.properties`，
项目里的那份改成注释说明。验证过：`./gradlew --version` 显示
`Launcher JVM: 21.0.12.1`，构建正常。

**结论：任何本机绝对路径都不要写进被 git 跟踪的文件。**
