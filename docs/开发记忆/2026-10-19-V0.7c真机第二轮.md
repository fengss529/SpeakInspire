# 2026-10-19 V0.7c：真机第二轮反馈

**271 条测试全绿**。提交 `3d63682`。APK：`outputs/suiji-v0.7c.apk`

## 1. 编辑页空白

根因：`remember { mutableStateOf(initialTitle) }` **没带 key**。

remember 只在首次组合求值一次，而 initialTitle 来自异步加载——
首次组合时它是空的，加载完成后值变了但 remember 不重新初始化。

改成 `remember(initialTitle)`。

**这个坑的特点：新建时完全正常，编辑时空白**，
所以开发时很容易漏掉。

## 2. 设置页「打不开」

不是打不开，是**保存后自动退回**：

    LaunchedEffect(state.saved) { if (state.saved) onBack() }

用户看到被弹回首页，再点设置时页面在别的 tab，像坏了。

设置页不是表单提交页，保存完应留在原地 + snackbar 提示。

**教训：自动退出最容易被误报成「坏了」。**
遇到「打不开」先查有没有自动跳转。

## 3. 点 AI 追问卡住（最严重）

根因是条件写反了：

    val needsFirstQuestion = rounds.isEmpty() ||
        rounds.lastOrNull()?.question.isNullOrBlank()

「最后一轮有问题就跳过」→ 「深化中」的记录（有历史轮次、未回答）
既不提问也不聚焦，页面是死的。

改成三分支：
- 最后一轮问题为空 → 重新问
- 有问题但没回答 → **不重复问，自动聚焦输入框**
- 全部答完 → 继续问下一个

### focusRequester 挂哪里

必须挂在 **BasicTextField 自己**上，挂在 Box 上无效。

### 兜底出路

空状态显示「还没开始 / 网络慢可再试一次 / [重新问一次]」。

**卡住时必须给一条出路** —— 否则用户只能退出，
且不知道是网络问题还是App 坏了。

## 三轮真机反馈的共同教训

第一轮：流程走不通（自动追问没实现）
第二轮：卡住（条件写反 + 没有兜底）
第三轮：空白（remember 没key）

**共同的模式是「异步状态与 UI 的同步」**：
- 异步加载的值 → remember 必须带 key
- 异步请求的中间态 → 三种状态都要处理（加载中/有内容/空白）
- 空白状态 → 必须给出路
