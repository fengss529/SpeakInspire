## 模拟器这次能用了（两个独立问题）

### 1. 缺 opengl32sw.dll → gfxstream 卡死

`-gpu swiftshader_indirect` 时日志停在 `Initializing gfxstream backend`，
进程活着、内存 400MB，但设备一直 offline。

原因：emulator 目录缺 `opengl32sw.dll`（Qt 的软件 OpenGL）。
从剪映目录复制了一份过去，立刻解决：
`D:\soft\JianyingPro\10.7.0.14095\opengl32sw.dll` → `D:\soft\AndroidSdk\emulator\`

代价：这是外部文件，SDK 升级可能丢。丢了就再复制一次。

### 2. 窗口跑到屏幕外（top = -730）

本机桌面 **1280x720**，AVD 是 1080x2400。
模拟器按缩放后的桌面居中，算出的窗口位置是 `(360, -730)`——整块在屏幕上方。

修法：`fix-emulator-window.ps1`（Win32 EnumWindows + MoveWindow，幂等、带重试），
`启动模拟器.bat` 在 boot 完成后自动调用。启动参数加 `-scale 0.4`。

### 3. 模拟器网络可以修

默认只有 `10.0.2.0/24`，没有默认网关。有 root（`adb root` 可用）：
```
adb shell ip route add default via 10.0.2.2 dev eth0
```
之后 TCP 443 通（`nc -w 5 api.deepseek.com 443` → exit=0）。
**之前记的「模拟器无法联网」是可以解决的。**

### 4. uiautomator dump 路径陷阱

Git Bash 会把 `/sdcard/ui.xml` 转换成 Windows 路径，
dump 写到奇怪的地方，表现为「dump 为空 = App 没渲染」的误判。
必须 `export MSYS_NO_PATHCONV=1`。

## 四个只在「前面成功了」才显形的洞

### 1. 追问页从来不显示待答的问题（最严重）

`DeepeningScreen` 只渲染：已回答的轮次 + 正在流式的内容。
流一结束，问题进了 rounds 但标着未回答 → **没有任何一处渲染它**。

用户看到：文字闪一下，页面空空，输入框写着「回应它」。只能盲猜作答。

之前所有关于 prompt / JSON / thinking 的排查，都绕过了这个事实：
**问题从来没有被画出来过。**

修：`DeepeningUiState.pendingQuestion` + 界面渲染它，5 条状态测试守着。

### 2. 成文页停在「还没开始」

`LaunchedEffect` 里 `load(id)` 后立刻判断 hasContent，
但 load 内部是 `viewModelScope.launch` —— 状态还没写进去，必然判成"没有文章"。
于是 compose() 在 noteId 还是空串时发出 → `findIdea("")` → null → 静默 return。

修：`load(noteId, autoCompose = true)`，顺序由 ViewModel 保证。

**又一个静默 return。**

### 3. 拒稿被当成文章

模型确实拒绝了，但写成 `{"title":"你聊得太少了…","paragraphs":[...]}` 的**正常文章形状**。
App 当成品渲染，还给「存进思考库」——用户能把一段拒稿说明存成文章。

修：本地预判。`materialSize < 300` 直接 Rejected，不发请求。
字数我们自己数得清，不该交给模型的自觉。

### 4. 收尾是死路

成文页说「回去再聊聊」，回去只看到收尾卡，输入框没了。

修：`reopen()` 清 finishedAt + FinishCard 加「还没说完，再聊几句」。

### 5. 骨架永远 0 段

`chooseAngle` 传 `ArticleDraft(dialogue = emptyList())`，
模型只有一句「切入角度：xxx」，没素材可拆。

修：传文章正文 + prompt 补 JSON schema。

## 经验

**每修好一步，下一层的问题才会露出来。**
这五个洞串在同一条链路上，前一个挡住了后一个。
所以「一次只测一个环节」是不够的 —— 必须真的走完整条。

# 附：模拟器导致电脑屏幕闪黑（TDR）

## 现象

开模拟器后电脑屏幕周期性黑一下，几秒恢复。

## 根因（已用事件日志确认）

Windows 系统日志：`显示器驱动程序 igfxn 已停止响应，并且已成功恢复`
（Provider=Display, Event ID=4101，时间与测试时段吻合）。

这是 **TDR（Timeout Detection and Recovery）**：Intel 核显驱动在 2 秒内
没响应完（`TdrDelay` 未设置=默认 2 秒），Windows 强制重置驱动 → 屏幕闪黑。

**不是显示器坏，也不是模拟器崩。**

## 为什么原来的参数会导致这个

`-gpu swiftshader_indirect` 只把 **3D 渲染**放到 CPU，
而**窗口合成仍然走 Intel 核显**（模拟器窗口是 Qt/OpenGL 应用）。
高频纹理上传 + 缩放合成，容易让 igfxn 超过 2 秒阈值。

## 已改

```
-gpu angle_indirect   # 走 D3D11，比 OpenGL 路径稳
-feature -Vulkan      # 关掉 Vulkan，少一条出问题的路径
```

实测新后端下渲染正常、App 界面完整、窗口摆正脚本照常工作。

## 还闪的话（备选，未执行）

1. `TdrDelay` 提到 60 秒（管理员 + 重启）：
   `reg add "HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers" /v TdrDelay /t REG_DWORD /d 60 /f`
2. 确认「硬件加速 GPU 计划」是关的（本机已确认：HwSchMode 未设置=默认关）
3. 降低 `-scale`（像素填充量与闪烁频率正相关）

## 顺带

窗口每次启动仍会跑到 `(360,-730)`，`fix-emulator-window.ps1` 每次都能摆正
（322x680 @ (8,4)）。说明窗口定位问题与缩放参数无关，脚本必须保留。

# V0.8.5：收尾时仍有问题在等回答 → 界面必须给输入框

## 症状（用户截图）

页面显示：三条已回答 + AI 的第 4 个问题 + **收尾卡「你说完了」**，没有输入框。
用户："无法继续追问"。

## 成因

用户在 AI **刚流完内容**时点了「收尾」：
`finishEarly()` 里 `skipTyping()` 把这段内容落地成待答轮次，
同时 `finished = true`。而输入框的条件是 `!finished` —— 被藏掉了。

结果：一个清清楚楚摆在你眼前的问题，下面没有输入框。

## 改法（三处，缺一不可）

1. 输入框条件：`!finished || pendingQuestion != null`
2. 收尾卡条件加 `!hasPending` —— AI 还在问，就不该宣布「你说完了」
3. `send()` 里：finished 时开口 → 自动重新打开会话

第 3 条容易漏：只做前两条会死结 —— 输入框回来了，用户答了，
但 finished 仍为 true，下一个问题永远不来。

**实现细节**：`send()` 里要用 `base = if (finished) current.copy(finished=false) else current`，
后续全部基于 base。直接用 `current.copy(...)` 会把刚清掉的 finished 带回来。

## 实测

同一条 3 轮记录：进入 → 问题在、输入框在、收尾卡不在
→ 输入一句 → 折叠 → 新问题「那件你期待会发生的好事，具体是什么？」正常到来。

353 条全绿。DeepeningFlowTest +2。

# 更正：`-gpu angle_indirect` 根本没生效

## 关键发现（模拟器退出时的完整日志）

```
ERROR | gpuChoiceBasedOnGpuOptions: Selected GPU option 'angle_indirect'
        is not valid, switching to 'auto' mode.
INFO  | emuglConfig_init: vulkan_mode_selected:host gles_mode_selected:host
```

**`angle_indirect` 是旧版的叫法，37.2 不认，静默回退到 `auto` = host 直通。**
也就是说上一轮那个"修复"让情况变得更依赖 Intel 核显，而不是更少。

同时还发现 `-scale` 也早就废了：
`WARNING | The -scale flag is obsolete and will be ignored.`
窗口大小一直是靠 `fix-emulator-window.ps1` 的 MoveWindow 兜住的。

## 37.2 的有效值（`emulator -help-gpu`）

auto / host / software / lavapipe / swiftshader / swangle

`swangle` = ANGLE 前端 + SwiftShader 后端，**GLES 和 Vulkan 全在 CPU**。

## 实测对比

| 参数 | 实际后端 | 结果 |
|---|---|---|
| `angle_indirect` | host（回退） | 直接压核显，TDR 风险最高 |
| `swiftshader_indirect` | swiftshader | guest 3D 在 CPU，但 Qt 窗口仍走系统 OpenGL |
| `swangle` | swiftshader（GLES+Vulkan） | 全 CPU，日志确认 `OpenGL ES 3.0 SwiftShader 4.0.0.1` |

swangle 下 App 渲染完全正常（记录列表、状态标签都在）。
代价：启动时系统 UI 慢到弹一次 ANR，点 Wait 就过。

## 教训

**启动参数被拒绝时模拟器不会报错退出，只会打一行 ERROR 然后静默回退。**
以后改 `-gpu` / `-feature` 这类参数，必须回头看日志里的
`emuglConfig_init: xxx_mode_selected:` 那一行，以它为准，
不能看命令行里写了什么。

## 仍未根除

Qt 窗口自身的 OpenGL 合成仍可能走系统 OpenGL（日志里有
`Software OpenGL failed. Falling back to system OpenGL`），
所以 TDR 不能保证完全消失。彻底兜底还是 `TdrDelay=60`。

# V0.8.8：点「收尾」没反应 —— 两条路同时被封死

## 现象

点顶栏「收尾」，界面上只少了一个按钮，其它什么都没变。

## 成因（我自己上一版改出来的）

V0.8.5 为了不让「AI 还在问却宣布你说完了」，给收尾卡加了 `!hasPending`。
但 `finishEarly()` 没有处理那个待答问题，于是：

- 收尾卡被 `!hasPending` 挡住
- 顶栏按钮被 `!finished` 挡住（此时 finished 已是 true）

**两条路同时封死**：问题在、能打字，却没有任何办法结束它。

## 改法（三处）

1. `finishEarly()` 丢掉末尾连着的未答轮次
   —— 点收尾的语义就是「我不答了」。
   `dropLastWhile { !it.answered }`，中间已回答的必须留住。
2. 顶栏「收尾」按钮：`!finished || pendingQuestion != null`
   —— 这是死结的出口。
3. `reopen()` 若手里没有可答的问题，主动 `askQuestion()`
   —— 收尾把问题丢了，不补一个输入框不会出现。

## 教训

**给 UI 加互斥条件时，必须同时检查另一条路是否也被挡住。**
`!hasPending` 和 `!finished` 单独看都对，叠起来就成了死锁。

## 实测

8 轮那条记录：进入 → 收尾按钮在 → 点它 → 待答问题消失
→ 「你说完了 · 说了 8 轮」+ 三个按钮。

V0.8.8 / versionCode 16。353 条全绿。

# V0.8.10：点「回去再聊聊」App 退出 —— FocusRequester 未初始化

## 崩溃栈（复现后从 logcat 抓到）

```
java.lang.IllegalStateException: FocusRequester is not initialized.
  at DeepeningScreenKt$DeepeningScreen$3$1.invokeSuspend(DeepeningScreen.kt:116)
```

## 成因

从成文页点「回去再聊聊」→ route 变 Deepening → **ViewModel 被复用**，
`focusTick` 还留着上次的值（> 0）。新组合里 `LaunchedEffect(focusTick)`
重新启动，立刻 `requestFocus()` —— 可这一帧输入框没渲染
（记录已收尾、无待答问题），`Modifier.focusRequester` 没挂到任何节点 → 抛异常。

## 改法

`canInput = !state.finished || state.pendingQuestion != null` 抽成唯一条件，
InputBar 渲染和自动聚焦都用它。再加 `runCatching` 兜边界帧。

**原则：需要 Modifier 才能生效的请求（focus / 滚动 / 手势），
必须和「那个节点会不会存在」用同一个条件。**

## 验证

修前：点按钮 → 进程数 0 + FATAL EXCEPTION
修后：点同一按钮 → 进程数 1 + 界面正常 + 崩溃 0

## 排查过程中的岔路（值得记）

1. 先怀疑 LazyColumn key 冲突（`it.hashCode()`）——查了数据库，
   三条会话都没有内容重复的轮次，**假设不成立**。
   但 key 还是改成了下标，因为那是真实隐患。
2. 又怀疑 swangle 软件渲染导致 ANR —— 查 /data/anr/，
   两条都是 **System UI 和 Messaging** 的，不是 App。
3. 最后换 `-gpu host`（快），复现一次就抓到了 Java 崩溃。

**教训：ANR 记录里要看 Subject 行是哪个进程，别一看有 ANR 就往自己头上安。**

## 启动参数定案

`-gpu host`。swangle 不压核显但慢到系统 UI 反复 ANR，不可用。
闪屏用 TdrDelay=60 根治。

# 真机反馈第二批修复（V0.8.11 / versionCode 19）

## ⚠️ 最大发现：`INSERT OR REPLACE` + 外键级联 = 静默删数据

用户报「点编辑只能改最初记录」「再打开追问记录丢失」，
其实是**同一个 bug**，而且它顺手删掉的还有文章和选题。

链路（已用 Python sqlite3 复现，也用生成的 SQL 交叉验证）：

```
Room 生成的 SpeakInspireDatabase_Impl.java:88  → PRAGMA foreign_keys = ON
@Insert(onConflict = REPLACE) 在 SQLite 里是「先 DELETE 再 INSERT」
  → 触发子表 ON DELETE CASCADE
  → 父行改一个字，子表整片清空
```

| 用户动作 | 被级联删掉的表 | 现象 |
|---|---|---|
| 点「编辑」改原始记录（noteDao.upsert） | deepening / article / script | 追问历史、文章、选题全没 |
| 重新成文保存（articleDao.upsert，id 固定 a_$noteId） | script | 选题凭空不见 |

**修法**：note / deepening / article / script / provider 五个 DAO 全改 `@Upsert`
（Room 生成 `EntityUpsertionAdapter` ＝ INSERT + `UPDATE ... WHERE id=?`，不删行）。
只有 `trashed` 保留 REPLACE（无子表）。

**验证方式（值得记）**：让假 DAO 去测这个 bug 一定全绿——内存实现没有外键。
真正的验证是读 `app/build/generated/ksp/.../NoteDao_Impl.java`：
修前是 `INSERT OR REPLACE INTO note`，修后是 `INSERT INTO note` + 独立 UPDATE 分支。
另加 `DaoWriteStrategyTest`（读源码数注解），因为 SQLite 层的行为测不出来。

## 其余五条

1. **键盘遮挡** — 不是缺 `imePadding`（输入栏本来就有），是**列表没跟着贴底**。
   键盘一弹 LazyColumn 可视高度变小但仍锚定原项，底部被切掉，最新问题排在最后。
   → `imePadding` 上移到根 Column（配 `consumeWindowInsets(padding)` 防重复），
   滚动 effect 增补 `imeVisible` 触发 + `withFrameNanos{}` 等一帧（否则读到 0 项）。
2. **弹窗闪现** — 答满第 5 轮瞬间 `completedRounds>=maxRounds` 成立而
   `pendingQuestion` 还空 → 收尾卡出现；第 6 问流进来又撤掉。
   → 上限真的生效：`send()` 在答满时直接收尾不再追问；判定收进
   `DeepeningUiState.showFinishCard`（排除 busy / streaming）。
3. **改不了回答** — 加 `updateAnswer(roundIndex, text)` + 历史气泡里的「改」+ 弹窗；
   原始记录卡右上角也加「编辑」。下标用 **rounds 原始下标**，
   不能用「第几个已回答」（中间夹未答轮次会改错句）。
4. 见上。详情页顺带把 `takeLast(2)` 改成全部列出（带 3 行省略）——
   只留两条也会让人觉得「记录丢了」。
5. **提问水** — `probeSystem` 加「素材在哪」「问题怎么才算贴着」两段：
   带两条示范（引用原话再追一层）和三条反面（「你能具体说说吗」这类换谁都成立）。
   给了可判断标准：「把他那句原话遮住，这个问题就不成立」。
6. **300 字门槛** — 降到 60（`ThinMaterial.THRESHOLD`）。
   另修一个隐蔽错误：`materialSize` 只数追问回答、**不算原始记录**，
